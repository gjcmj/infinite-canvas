## 1. 架构概览

```
浏览器前端
├── IndexedDB（本地缓存层）
└── 自动同步层 ──→  /api/storage/*  哑文件存储
    AI 调用层  ──→  /v1/*           OpenAI 兼容代理
                     /api/models     模型列表
```

两条链路完全解耦：

| 链路 | 前端文件 | 后端端点 | 用途 |
|------|---------|---------|------|
| 持久化流 | `cloud-storage.ts` + `cloud-sync.ts` + `cloud-app-sync.ts` | `/api/storage/*` | 画布/资产/媒体数据云同步 |
| AI 生成流 | `model-gateway.ts` + 原有 `image.ts`/`video.ts`/`audio.ts` | `/api/models` + `/v1/*` | 模型网关，用户只选模型 |

**关键设计决策**：后端存储是**按路径存取的哑文件系统**，不解析任何文件内容。
云存储为**唯一事实源**，浏览器 IndexedDB 仅为缓存层。

### 1.1 四个域及其同步方式

前端有四个数据域需要同步到云端，但使用**两种不同的同步驱动**：

| 域 | 同步驱动 | 远端文件形态 | 说明 |
|------|---------|-------------|------|
| `canvas`（画布） | `cloud-app-sync.ts`（新 per-canvas） | `canvas/index.json` + `canvas/projects/{id}.json` + `canvas/files.json`（媒体清单） | 逐画布增量同步 + 媒体按 bytes 增量 | 
| `assets`（我的资产） | `app-sync.ts`（旧 single manifest） | `assets/manifest.json` | 全量合并 |
| `image-workbench`（生图工作台） | `app-sync.ts`（旧 single manifest） | `image-workbench/manifest.json` | 全量合并 |
| `video-workbench`（视频创作台） | `app-sync.ts`（旧 single manifest） | `video-workbench/manifest.json` | 全量合并 |

> ⚠️ **注意事项**：
> - 四个域共用同一套**底层传输层**（`/api/storage/file` GET/PUT/DELETE），只是同步策略不同
> - assets/workbench 域的 manifest 文件读写全部走 `/api/storage/file?path=`，对后端无任何额外接口要求

## 2. 鉴权与通用约定

### 2.1 鉴权方式

所有接口使用 `Authorization: Bearer <token>`。

Token 来源（前端已支持三种，由部署形态决定）：

| 方式 | 前端代码位置 | 说明 |
|------|-------------|------|
| `window.__APP_CONFIG__.authToken` | `use-auth-store.ts:13` | 运行期页面注入，适合容器化部署 |
| `VITE_AUTH_TOKEN` 环境变量 | `use-auth-store.ts:14` | 构建期注入 |
| UI 用户输入 → localStorage | `use-auth-store.ts:16-22` | 开发期/自托管场景，在「云端存储」页填写 |

前端 Token 管理文件：`web/src/stores/use-auth-store.ts`

### 2.2 通用格式

- 数据格式：JSON（`Content-Type: application/json`），文件传输除外
- 错误响应统一格式：

```json
{ "error": { "code": "NOT_FOUND", "message": "文件不存在" } }
```

- CORS 要求（前后端不同源时）：

```
Access-Control-Allow-Origin: <前端域名>
Access-Control-Allow-Methods: GET, PUT, POST, DELETE, OPTIONS
Access-Control-Allow-Headers: Authorization, Content-Type, If-Match, Range
```

**推荐前后端同域反代**（如 `/api`、`/v1` 直接反代到后端），可省去 CORS 配置。

## 3. 云端存储接口（4 必需 + 2 可选）

设计为**基于路径的哑文件存储**：后端不理解文件内容，只按路径存取二进制。
路径根目录按 token 对应的用户隔离（多用户天然隔离）。

> ⚠️ 以下接口中所有 `path` 参数为相对用户存储根的路径，用 `/` 分隔。
> 后端必须校验 `path`，拒绝 `..` 越界。

### 3.1 `GET /api/storage/health` — 连接测试（必需）

前端调用位置：`cloud-storage.ts:105-114`

```
GET /api/storage/health
Authorization: Bearer <token>
```

**响应**：

| 状态码 | Body |
|--------|------|
| 200 | `{ "ok": true, "user": "xxx", "usage": { "used": 123456, "quota": 1073741824 } }` |
| 401 | `{ "error": { "code": "UNAUTHORIZED", "message": "..." } }` |

**前端行为**：

- 仅用于 UI「测试连接」按钮
- 显示 `"连接成功"` / `"认证失败，请检查 Token"` / `"云端服务不可用"`
- `quota` 不强制要求精确，可为 `-1`（表示无限制）

### 3.2 `GET /api/storage/file?path=` — 下载文件（必需）

前端调用位置：`cloud-storage.ts:117-125`

```
GET /api/storage/file?path={relativePath}
Authorization: Bearer <token>
```

**参数**：

| 参数 | 类型 | 说明 |
|------|------|------|
| path | string(query) | 如 `canvas/index.json`、`canvas/files/image_V1StGXR8.png`（storageKey 中的非法字符已替换为下划线） |

**响应**：

| 状态码 | 说明 |
|--------|------|
| 200 | 二进制 body，`Content-Type` 为上传时保存的 MIME |
| 206 | **必须支持 Range 请求头**，返回 `Content-Range`（见下文）|
| 404 | **前端约定 404 = null，不算错误** |
| 401 | 未授权 |

**关键要求**：

1. **必须支持 `Range` 请求头**（返回 `206 Partial Content` + `Content-Range`）
   - 直存增强启用后（第 5 节），`<video>` 直接播放云端 URL
   - 不支持 Range → 视频拖进度条失效、seek 触发整段重下
2. **建议支持 `HEAD` 请求** + `ETag` / `Last-Modified` 缓存头
   - 配合浏览器 HTTP 缓存，减少重复下载
   - 前端 `readRemoteJsonWithEtag`（`cloud-storage.ts:217-232`）依赖 `ETag` 响应头

**前端下载流程**：

```typescript
// cloud-storage.ts — 下载文件
const response = await cloudFetch(buildUrl(config, path));
if (response.status === 404) return null; // null = 不存在
return response.blob();
```

### 3.3 `PUT /api/storage/file?path=` — 上传文件（必需）

前端调用位置：`cloud-storage.ts:133-156`（普通上传）`cloud-storage.ts:173-197`（带 If-Match）

```
PUT /api/storage/file?path={relativePath}
Authorization: Bearer <token>
Content-Type: <实际 MIME 或 application/octet-stream>
Body: 原始二进制
```

**语义要求（同步引擎依赖）**：

| 行为 | 要求 |
|------|------|
| 同路径重复上传 | **幂等覆盖**（指最终结果是覆盖，非必须幂等 HTTP） |
| 父目录 | **隐式创建**（前端不再发建目录请求） |
| 大文件 | 流式落盘，勿全量缓冲 |
| 乐观锁 | 见下文 |

**乐观锁机制（核心！）**：

| 场景 | 请求头 | 后端行为 |
|------|--------|---------|
| 首次写入（文件不存在） | 无 `If-Match` | 创建文件，返回 200 |
| 首次写入（文件已存在） | 无 `If-Match` | **覆盖写入**（视为用户明确覆盖） |
| 覆盖写入（存在 etag） | `If-Match: <etag>` | 校验 etag：匹配 → 写入 200；不匹配 → **返回 412** |
| 覆盖写入（不传 If-Match） | 无 `If-Match` | **可选**：返回 412 要求带 etag，或允许覆盖 |

> 后端实现时注意区分：
> - 不传 `If-Match` = 强制写入（首次写入或用户强制覆盖）
> - 传 `If-Match` = 条件写入（etag 不匹配必须 412）

**前端乐观锁重试循环**（`cloud-app-sync.ts:213-261` 的 `writeIndexWithRetry`，重试循环在 `:236-260`）：

```
① 获取远端 index.json + 当前 etag
② 本地合并后，用 uploadWebdavFileWithEtag 写入（带 If-Match）
③ 收到 412 → 重读远端 → 重新合并 → 用新 etag 重试
④ 最多 3 次，超过抛出异常
```

**响应**：

| 状态码 | Body |
|--------|------|
| 200 | `{ "path": "...", "bytes": 12345, "etag": "abc" }` |
| 401 | 未授权 |
| 412 | 乐观锁冲突（前端的 `uploadWebdavFileWithEtag` 会捕获并抛 `"CONFLICT"`）|
| 413 | 超出配额限制 |

### 3.4 `DELETE /api/storage/file?path=` — 删除文件（必需）

前端调用位置：`cloud-storage.ts:164-170`

```
DELETE /api/storage/file?path={relativePath}
Authorization: Bearer <token>
```

**响应**：

| 状态码 | 说明 |
|--------|------|
| 200 | 已删除或路径不存在（**404 也返回 200**，简化前端）|
| 401 | 未授权 |

**当前前端实际行为**（根据 F3 决策）：

- 前端**目前不主动调用 DELETE**（后端软删除策略）
- `deleteWebdavFile` 已实现但未在同步流程中联调
- 文件清理在 v2 规划中

### 3.5 `POST /api/storage/batch` — 批量上传（可选，强烈建议）

```
POST /api/storage/batch
Content-Type: multipart/form-data
```

**请求体**：

| part | 类型 | 说明 |
|------|------|------|
| `meta` | JSON string | `[{ "path": "canvas/files/a.png", "part": "f1" }, ...]` |
| `f1`, `f2`, ... | binary | 各文件二进制内容 |

**响应**：

```json
{ "results": [{ "path": "...", "bytes": 123, "status": "ok" }] }
```

**价值**：单个画布可能几十张图，逐个 PUT 慢。批量上传用一个 multipart 请求减少 RTT。

### 3.6 `GET /api/storage/list?prefix=` — 列表/统计（可选）

```
GET /api/storage/list?prefix=canvas/files/
→ { "files": [{ "path": "...", "bytes": 123, "etag": "..." }] }
```

### 3.7 远端目录结构（前端约定，后端无需理解内容）

```text
{namespace}/canvas/index.json                     # 画布索引（1 个：项目 id/标题/updatedAt 清单）
{namespace}/canvas/projects/{id}.json              # 每画布一个 JSON（N 个画布 = N 个文件）
{namespace}/canvas/files/{safeFileName(storageKey)}.{ext} # 画布域媒体文件（扁平，按 storageKey 去重，非法字符替换为下划线）
{namespace}/canvas/files.json                     # 画布域媒体清单（固定 1 个：storageKey / path / mimeType / bytes）
{namespace}/assets/manifest.json                   # 资产域清单（固定 1 个，与画布数量无关）
{namespace}/image-workbench/manifest.json          # 图片工作台清单（固定 1 个）
{namespace}/video-workbench/manifest.json          # 视频工作台清单（固定 1 个）
```

> ⚠️ **canvas 域没有画布数据 manifest.json**，它采用 per-canvas 布局 + 一个媒体清单：
> - `index.json` 是**索引清单**（列出所有画布的 id/title/updatedAt + 删除墓碑），自动同步只在画布被编辑时更新对应那一个 `projects/{id}.json`
> - `canvas/files.json` 是**媒体清单**：记录每个媒体的 storageKey / 实际 path / mimeType / bytes。前端本地缺 Blob 时按它补下载，远端 bytes 与本地一致时不重传（这是"不再全量重传媒体"的依据）
> - 创建 N 个画布 → 远端产生 **1 个 index.json + 1 个 files.json + N 个 projects/*.json**
> - 其余三域（assets / image-workbench / video-workbench）才是**各固定 1 个 manifest.json**，与画布数量无关

- `{namespace}` 由 `config.directory` 控制，通常为空或用户 ID
- `safeFileName` 把 storageKey 中的非法字符替换为 `_`（如 `image:V1StGXR8.png` → `image_V1StGXR8.png`）
- 画布按项目拆分文件（B 方案 per-canvas），而非单个全量 manifest

### 3.8 非功能性要求

| 要求 | 说明 |
|------|------|
| 单文件上限 | ≥ 1GB（视频 Blob 可能很大）|
| 乐观锁 | PUT 必须支持 `If-Match`，冲突返回 412 |
| Range 请求头 | GET 必须支持，视频播放依赖此能力 |

### 3.9 `POST /api/storage/flush` — 同步信号（可选）

页面关闭前，前端用 `navigator.sendBeacon` 发一个"有未同步改动"的信号（**只发信号，不携带数据**）：

```
POST /api/storage/flush
Body: {"dirty": true}
```

- 后端可忽略该端点（返回 404 不影响前端，前端不读响应体）
- 真正落盘的同步由 `visibilitychange` 的 5s 防抖与编辑停止防抖（默认 30s）完成；IndexedDB 里始终有最新数据，下一次启动也会同步
- 前端用 `sendBeacon(url, JSON.stringify(...))` 发的是**字符串**，浏览器带 `Content-Type: text/plain;charset=UTF-8`，后端不要按 `application/json` 严格校验
- **不实现这个端点没有任何功能影响**：前端不读响应、不重试、不等结果；数据已经在 IndexedDB 里，启动同步与编辑停止防抖都会上传。它只是一个"用户要走了"的可选提示（可用于后端即时落盘、会话清理或埋点）
- **该请求不带 `Authorization`**：`sendBeacon` 无法设置自定义请求头，所以后端要么把它当"未鉴权信号"处理，要么按 401/404 忽略——对前端都没差别；也不要基于它做需要可信身份的判断

## 4. 模型网关接口

### 4.1 `GET /api/models` — 模型列表（必需）

前端调用位置：`model-gateway.ts:19-51`

```
GET /api/models
Authorization: Bearer <token>
→ 200 {
  "models": [
    { "id": "gemini-3-pro-image", "name": "Gemini 3 Pro 图片", "capability": "image" },
    { "id": "kling-3.0",          "name": "可灵 3.0",          "capability": "video" },
    { "id": "gpt-5.5",            "name": "GPT-5.5",           "capability": "text" },
    { "id": "gpt-4o-mini-tts",    "name": "TTS 语音",          "capability": "audio" }
  ]
}
```

**`capability` 取值必须对齐前端四值枚举**：

```typescript
type ModelCapability = "image" | "video" | "text" | "audio";
```

前端按此过滤下拉列表，其他值会被忽略。

**前端缓存策略**：

- 成功获取后写入 `localStorage`，TTL 1 小时
- `getCachedGatewayModels()` 用于离线 / 启动时预览
- `ensureGatewayChannel()` 在应用启动时调用，优先用缓存

### 4.2 OpenAI 兼容代理端点（必需）

网关对外**只暴露 OpenAI 格式**，后端负责把各家协议翻译掉。

| 端点 | 方法 | 用途 | 前端文件 |
|------|------|------|---------|
| `/v1/images/generations` | POST | 文生图 | `services/api/image.ts` |
| `/v1/images/edits` | POST | 图生图 (**multipart FormData**) | `services/api/image.ts` |
| `/v1/responses` | POST | 文本对话 (`stream: true`) | `services/api/image.ts`（`requestStreamingResponse`） |
| `/v1/videos` | POST | 视频任务创建 (**FormData 多字段**) | `services/api/video.ts` |
| `/v1/videos/{id}` | GET | 视频任务轮询 | `services/api/video.ts` |
| `/v1/videos/{id}/content` | GET | 视频结果下载 | `services/api/video.ts` |
| `/v1/audio/speech` | POST | TTS (JSON → blob) | `services/api/audio.ts` |
| `/v1/models` | GET | (可选)可复用 `/api/models` 数据 | — |

**请求路由规则**：`model` 字段值为 `/api/models` 返回的 `id`，后端据此路由到对应上游。

**重点要求**：

| 功能 | 要求 |
|------|------|
| SSE 流式 | `/v1/responses` 的 `stream: true` 模式**必须透传**，不能缓冲完再返回 |
| `/v1/images/edits` | multipart FormData，含 `image[]`，需流式读取 body |
| `/v1/videos/{id}` | 长任务，后端需保持任务状态直至完成/失败 |
| `/v1/videos/{id}/content` | 流式响应，勿全量缓冲（可能几百 MB）|

**鉴权**：所有 `/v1/*` 同样带 `Authorization: Bearer <token>`；上游服务商的 Key **永不出后端**。

### 4.3 虚拟渠道机制（前端视角，了解即可）

前端将网关视为一个 `id = "gateway"` 的虚拟 `ModelChannel`，注入现有渠道体系：

```typescript
{
  id: "gateway",
  name: "云端模型",
  baseUrl: "<网关地址>",
  apiKey: "",                    // 不存于此，token 由 use-auth-store 管理
  apiFormat: "openai",           // 强制 OpenAI 格式
  models: [/* GET /api/models 结果 */]
}
```

前端 `model-gateway.ts` 负责拉取模型列表、刷新缓存、确保虚拟渠道存在。

## 5. 服务端直存（增强，可选但推荐）

### 5.1 问题

基线方案中，上游生成的 100MB 视频 = 浏览器先下载 100MB → 存 IndexedDB → 自动同步再上传 100MB，用户下行 + 上行各走一遍。

### 5.2 方案

结果文件由**后端直接写入用户云存储**（内网/同机房直传，零用户带宽）。

**流程**：

```
① 前端 POST /v1/videos（参考图经网关送上，与直存无关）
② 后端调上游生成 → 拿到结果 → 服务端直存为 canvas/files/video:V1St....mp4
③ 轮询响应新增字段：

GET /v1/videos/{id}
→ {
    "status": "completed",
    "storageKey": "video:V1St...",     // 后端已直存的 storageKey
    "path": "canvas/files/video:V1St....mp4",
    "bytes": 104857600
  }

④ 前端：
   节点 metadata.storageKey = "video:V1St..."
   content = 云端 URL（/api/storage/file?path=...），画布立刻可播放
   IndexedDB 仅作缓存（不是离线保障）
```

### 5.3 前端适配（**尚未实现**，仅类型预留）

- `VideoTaskResponse` 类型已包含 `storageKey` / `path` / `bytes` 字段（预留）
- ⚠️ 前端**尚未接线**：节点不会自动引用云端 URL，仍走"下载 → 存 IndexedDB → 同步上传"的现有流程
- ⚠️ 原设计的 `collectChangedMedia` 已不存在：媒体上传统一由 `uploadChangedMedia`（`cloud-app-sync.ts`）按 `canvas/files.json` 清单的 bytes 比对决定是否上传；接直存时只需把服务端直存的文件写入清单条目、不上传

### 5.4 前端判断逻辑（设计，**尚未实现**）

```typescript
// 设计（尚未实现）：后端返回 storageKey 时，前端不再下载结果文件
// 1. 节点的 metadata.storageKey = 返回的 storageKey
// 2. content 直接用云端 URL 赋值
// 3. 同步时对 .bytes 已匹配的服务端直存文件不上传
```

## 6. 服务端引用（增强，与 5 配套）

### 6.1 问题

生成请求的参考图/参考视频必须经浏览器上传 → 后端转发，浪费带宽。

### 6.2 方案

参考图**不必经过浏览器上传**，直接引用用户云存储中的文件。

**请求格式**（二选一或混用）：

```typescript
// 方式 A（现有）：直接上传二进制
image[] = File  ← 本地新图/尚未同步的图

// 方式 B（新增）：引用云存储文件
image_ref[] = "image:V1St..."  ← 引用云存储中的 storageKey（或完整 path）
```

**视频同理**：`video_ref[]` 用于参考视频。

### 6.3 后端职责

收到 `*_ref` 字段后，从该用户云存储服务端读取文件，转发上游。
文件零浏览器带宽。

### 6.4 前端判断逻辑（设计，**尚未实现**）

```
参考图的 storageKey 已在 canvas/files.json 清单（或对应域的 manifest）里 → 传 image_ref[]
否则（新图未同步）→ 传 image[]（当前唯一路径）
两条路并存，兼容自动同步的防抖窗口
```

## 7. 前端驱动行为一览

### 7.1 前端如何调用后端（调用链）

| 前端触发时机 | 调用链路 | 后端端点 |
|-------------|---------|---------|
| 用户打开配置弹窗 → 点「测试连接」 | `cloud-storage.ts → cloudFetch()` | `GET /api/storage/health` |
| 应用启动时 | `cloud-sync.ts → syncCanvasDomain()` → `cloud-storage.ts` | `GET /api/storage/file?path=canvas/index.json` |
| 启动时读取媒体清单 | `cloud-app-sync.ts → readFilesManifest()` | `GET /api/storage/file?path=canvas/files.json` |
| 启动时后台刷新网关模型 | `cloud-sync.ts → refreshGatewayModels()` | `GET /api/models` |
| 同步启动后（有脏画布） | `cloud-app-sync.ts → uploadWebdavFile()` | `PUT /api/storage/file?path=canvas/projects/{id}.json` |
| 合并远端新画布 | `cloud-app-sync.ts → downloadWebdavFile()` | `GET /api/storage/file?path=canvas/projects/{id}.json` |
| 补齐本地缺失媒体 | `cloud-app-sync.ts → downloadMissingMedia()` | `GET /api/storage/file?path=canvas/files/{fileName}` |
| 上传媒体文件（仅远端缺失或 bytes 不一致时） | `cloud-app-sync.ts → uploadChangedMedia()` | `PUT /api/storage/file?path=canvas/files/{fileName}.{ext}` |
| 同步时写回索引 | `cloud-app-sync.ts → writeIndexWithRetry()` | 先 `GET`（带 etag）→ `PUT`（带 If-Match）|
| 同步写回媒体清单 | `cloud-app-sync.ts → uploadWebdavFile()` | `PUT /api/storage/file?path=canvas/files.json`（内容无变化时跳过） |
| 同步资产/工作台域 | `cloud-sync.ts → syncNonCanvasDomains()` → `app-sync.ts → syncDomain()` | `GET/PUT /api/storage/file?path=assets/manifest.json` 等（canvas 域已跳过） |
| 用户选择模型 | `model-gateway.ts → fetch()` | `GET /api/models` |
| AI 生成请求 | `image.ts / video.ts / audio.ts → fetch()` | `POST /v1/*` |
| beforeunload | `cloud-sync.ts → sendBeacon()` | `POST /api/storage/flush`（可选，信号型）|

### 7.2 错误处理对照

| 前端异常消息 | 触发条件 | 对应 HTTP |
|-------------|---------|-----------|
| "认证失败，请检查 Token" | `health` / `models` 返回 401 | `401` |
| "请求超时" | 超过 120s 无响应 | 任何端点 |
| "连接失败" | TypeError（网络不通）| 任何端点 |
| "CONFLICT"（乐观锁冲突） | PUT 返回 412 | `412` |
| "超出配额限制" | PUT 返回 413 | `413` |
| null（404 正常） | GET 返回 404 | `404` |
| "上传失败 (xxx)" | PUT 返回其他 4xx/5xx | 其他状态码 |
- 401 时前端还会自动打开「云端存储」配置页签，引导重新填写 Token

### 7.3 启动同步流程

```
① main.tsx → initCloudSync()
② ensureGatewayChannel() — 确保虚拟渠道存在，并在后台 refreshGatewayModels() 刷新模型列表
③ setTimeout 等待 React 渲染完成 → 等待 zustand persist hydration 完成
④ 订阅 canvas / asset store（JSON.stringify 引用比较）
⑤ 启动时**无条件 doSync()** 一次：本地为空则全量拉取；本地非空则按 `updatedAt` 拉取远端较新画布，并按 `canvas/files.json` 补齐缺失媒体
⑥ 此后由编辑停止防抖（默认 30s，可配）、手动「立即同步」、visibilitychange（5s 防抖）触发
```

## 8. 开发顺序建议

### 第一阶段：存储底座（MVP）

```
优先级：P0
后端接口：/api/storage/health + /api/storage/file (GET/PUT)
```

1. 实现 `GET /api/storage/health`（量最简单的开始）
2. 实现 `PUT /api/storage/file?path=`（支持 If-Match）
3. 实现 `GET /api/storage/file?path=`（支持 Range + ETag）
4. 前端默认直连真实后端（无需改动）；只有本地联调时才需要 `VITE_CLOUD_MOCK=true` 走内存模拟数据

**验证方式**：

- 前端「云端存储」页签配置网关地址 + Token → 点「测试连接」→ 成功
- 点「立即同步」→ 画布数据写入云端
- 新开浏览器 → 同步回来

### 第二阶段：模型网关

```
优先级：P0
后端接口：/api/models + /v1/* 代理
```

1. 实现 `GET /api/models`（返回模型列表）
2. 实现 `/v1/responses`（SSE 流式，AI 对话核心）
3. 实现 `/v1/images/generations`（文生图）
4. 实现 `/v1/audio/speech`（TTS）
5. 实现 `/v1/videos` + 轮询 + 下载（视频生成）
6. 实现 `/v1/images/edits`（图生图）

**验证方式**：

- 前端配置网关地址 → 模型下拉列表出现
- 选择云端模型 → AI 对话/图片生成正常工作

### 第三阶段：增强（可选但推荐）

```
优先级：P1
后端接口：服务端直存 + 服务端引用
```

1. 视频任务完成时后端直存到 `/api/storage/file`
2. 轮询响应携带 `storageKey` / `path` / `bytes`
3. 支持 `image_ref[]` / `video_ref[]` 引用型参数

**验证方式**：

- 视频生成完成后前端节点即时可播放（不等待上传）
- 参考图已同步时不走浏览器上传

### 第四阶段：批量与运维

```
优先级：P2
后端接口：/api/storage/batch + /api/storage/list
```

1. 批量上传 multipart 接口
2. 文件列表/统计接口
3. 软删除超期文件清理策略

### 画布索引 `canvas/index.json`（核心数据结构）

这是云端画布同步的核心文件，**后端不需要理解其内容**，只需按路径存取二进制即可。但了解其结构有助于排查同步问题。

```typescript
type CanvasIndex = {
    /** 固定值 "infinite-canvas"，标识格式 */
    app: "infinite-canvas";
    /** 固定值 "canvas"，标识域 */
    domain: "canvas";
    /** 固定值 1，版本号，未来格式升级时递增 */
    version: 1;
    /** 索引文件最后导出时间，ISO 8601 字符串，如 "2026-10-08T12:00:00.000Z" */
    exportedAt: string;
    /**
     * 活跃项目列表
     * 每个项目只存摘要信息，详细内容在 canvas/projects/{id}.json
     * 同步引擎据此决定：
     *   - 本地有、远端也有 → 比较 updatedAt，新版本上传覆盖
     *   - 本地有、远端无 → 上传新增
     *   - 本地无、远端有 → 下载 canvas/projects/{id}.json
     */
    projects: Array<{
        /** 画布项目 ID（UUID），对应 canvas/projects/{id}.json */
        id: string;
        /** 画布标题，下载列表展示用 */
        title: string;
        /** 最后更新时间，ISO 8601 字符串，合并冲突时新版本赢 */
        updatedAt: string;
    }>;
    /**
     * 已删除项目墓碑列表
     * 墓碑无条件赢过本地未删除状态：
     *   如果远端索引中有 deleted.id，即使本地还有该项目也要删除
     */
    deleted: Array<{
        /** 被删除的项目 ID */
        id: string;
        /** 删除时间，ISO 8601 字符串 */
        deletedAt: string;
    }>;
};
```

> **消费文件**：`cloud-app-sync.ts`
> - 读取：`readRemoteJson<CanvasIndex>(config, indexFilePath())` → 第 75 行（与 `readFilesManifest()` 一起 Promise.all 读取）
> - 合并：`mergeIndex(projects, deletedProjects, remoteIndex)` → 第 78 行，用 updatedAt 和墓碑做三路合并（墓碑无条件赢）
> - 写回：`writeIndexWithRetry()` → 定义在第 213 行（重试循环 236-260，最多 3 次），调用点在第 138 行
>
> **常见数据流**：
> ```
> ① 启动时读远端 canvas/index.json 与 canvas/files.json（GET，带 ETag）
> ② 与本地 store 合并（按 id/updatedAt，墓碑无条件赢）
> ③ 下载远端较新或本地缺失的 projects/{id}.json（GET）
> ④ 按 canvas/files.json 补齐本地缺失的媒体（GET canvas/files/{fileName}）
> ⑤ 上传变更的 project JSON、远端缺失或 bytes 不一致的媒体（PUT），并写回 canvas/files.json
> ⑥ 乐观锁写回 index.json（PUT 带 If-Match，412 则重试）
> ```

## 关键风险提醒

| 风险 | 说明 | 缓解 |
|------|------|------|
| index.json 并发写 | 两设备同时合并索引 → 后写覆盖先写 | 乐观锁（If-Match）+ 前端重试（3 次）|
| 视频流式带宽 | 大型视频 SSE 响应全量缓冲导致 OOM | 始终流式响应，勿全量缓冲 |
| SSE 断连 | 文本对话 SSE 中途断开 → 用户看到不完整回答 | 浏览器自动重连；后端可考虑标记已完成事件 |
| 长视频状态存储 | 网关重启后任务状态丢失 → 轮询接口返回 404 | 任务状态外置 Redis/DB |
